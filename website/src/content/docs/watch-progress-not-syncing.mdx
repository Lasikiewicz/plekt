*Plekt steps reviewed against the v2.2.0 release candidate.*

When a film or episode is watched on one server but stays unwatched, or keeps the wrong resume position elsewhere, trace one event before changing anything. Repeatedly toggling watched state can make it harder to tell which service has the latest value.

## Trace one title

1. Choose one film or episode and one direction, such as Plex to Jellyfin. Note the source, destination, title, year or episode, and approximate event time.
2. Open the source service and confirm that it recorded the watched state or playback position. If the source is wrong, fix playback reporting there first.
3. Confirm how the source reaches Plekt. Plex uses its built-in WebSocket notifications plus scheduled checks. Jellyfin can use the Plekt plugin or webhooks alongside polling. Follow the [Jellyfin setup guide](/docs/jellyfin/) and choose one event method, not both. Without an event, playback checks run every 5 minutes while idle and every 10 seconds once playback is detected, so a new session can take a few minutes to appear.
4. Confirm Plekt is connected to the intended server and account. The Plekt host must be able to reach the server URL; a connection that works in your browser does not prove that the host can reach it.
5. Check that the destination contains the same title. Compare the year, season, episode number, and provider identity before correcting a match. Duplicate titles and differently matched episodes can look like failed syncs.

Open [Sync Activity](/docs/sync-tools/#read-an-activity-row), find the newest event for the title, and expand its group. Check each destination's result and reason:

- **Skipped** often means no matching item was found, the destination is not configured, or the item was outside the operation's scope.
- **Failed** means the provider request did not complete. Check [Settings → Logs](/docs/settings/logs/) for the provider detail.
- **Success** means Plekt recorded a successful delivery response. Confirm the resulting state in the destination service too.

Correct the cause shown in the row. If a retry is available, retry only the affected item or destination, then confirm that its result updates. Avoid a library-wide replay for a single mismatch.

## If it still disagrees

Make a backup before changing credentials, resetting history, or restoring data. Keep the event time and non-secret error text for a support report. Do not post API keys, webhook tokens, private library names, or account identifiers.

Plekt can show and retry its own provider deliveries. It cannot repair a provider-side outage or guarantee a match for every title. See the [Plex integration guide](/docs/plex/), [Jellyfin integration guide](/docs/jellyfin/), and [Sync Activity guide](/docs/sync-tools/).
