Use **Sync Activity** when you need to answer “what happened?” rather than only “is the
connection healthy?”.

It groups activity by movie or show while preserving every event, source, destination, result,
and the reason behind a skipped or failed delivery.


## Read an activity row


An activity row can identify:

- the media item and requested action;
- the source platform and time;
- each destination selected for delivery;
- **success**, **skipped**, **partial**, or **failed** status;
- the reason a destination was skipped or failed; and
- a retry or log action when one is available.

The list header shows how many media groups are loaded and how many have issues on the current
page. Click the failed-count summary pill to show only groups with failed results; click it
again to restore the full page. Search and filtering do not delete or hide the underlying
history.

Open a group to load its current activity inline. The expanded group shows the newest current
result for each movie or episode, resume checkpoints, and target results, newest first, with
**Load older events** for the full audit history. Expected missing-library and unconfigured-target
skips remain separate from real failures.
The title button opens the matching local or provider detail route without collapsing the
group.

The [sidebar Sync indicator](/docs/navigation/#sidebar-status-and-actions) is only a summary.

Use [Sync Activity](/docs/sync-tools/#read-an-activity-row) and
[Settings → Logs](/docs/settings/#logs) for the detailed reason.

A **skipped** result usually means there was no matching item, the destination was not
configured, or the item was outside the operation scope.

Check [Settings → Sync → Sync Issues and Match Report](/docs/settings/#sync-issues-and-match-report).

A **failed** result means the request or provider operation did not complete. Retry and dismiss
actions keep their public failure response generic; use the current result and
[Settings → Logs](/docs/settings/logs/) for deeper diagnostics.

Check [Settings → Connections](/docs/settings/#connections),
[Settings → Metadata](/docs/settings/#metadata-providers), and
[Settings → Logs](/docs/settings/#logs).

## Retry one result


Use a row-level retry after correcting the specific cause:

1. Open **Sync Activity** from the sidebar Sync indicator.
2. Find the newest row for the title.
3. Expand or open the row and read the destination reason.
4. Correct the match, connection, or provider setting named by that reason.
5. Choose **Retry failed** or the available item retry. For a Trakt `not_found` result, use
   the show-match repair described below.
6. Confirm that the result updates in place and shows success or a useful reason.

Retrying is safe because duplicate delivery is protected by the event and media identity.

Do not use a full replay to fix one wrong title when a targeted retry is available.

The retry preserves the previous outcome in the raw debug data. Targets that are now
unconfigured are reported as **skipped**, and targets that were not retried keep their prior
result, so the resolved group can leave the failed count without creating a stale duplicate
row.

## Retry all failed

**Retry all failed** retries failed or skipped items across the full history, not only the
visible page. Plekt discovers the real total before confirming and runs the retry as a
background job that survives navigation, reloads, and a closed tab.

It runs as a background job, so it can continue while the tab is closed or you navigate
away.

Use it only after fixing the shared cause, such as a server being back online or a provider
key being corrected.

When the job finishes, read the resulting statuses in Sync Activity.

Items with no configured destination can remain skipped by design.

## Restore attention and match repair

An authoritative watch-history restore can leave a grouped **Sync - Attention Needed** panel
when a media-server projection still needs repair. Expand a show to review its episodes,
retry or skip a batch, or choose a target-specific retry. If the saved identity is no longer
enough for a direct retry, **Fix match** opens the normal title-matching flow; rerunning the
restore uses the corrected identity. The restore fence releases after every outstanding item
is repaired or deliberately skipped.

### Trakt show-match repair

When an episode's Trakt result is `not_found`, the saved show identity may no longer resolve in
Trakt. Open the affected show group and choose **Fix show match & retry all**. Plekt repairs
the show identity, rematches every stored episode, warms the corrected TV metadata and posters,
and retries the current failed entries. The individual **Fix show match** action is available
when only one result needs attention.

If Trakt does not contain the show, choose **Dismiss Trakt errors** for the group or
**Dismiss Trakt error** for one item. This intentionally skips only the Trakt target; it does not
delete local watch history or suppress delivery to other configured destinations. Older audit
events are preserved, while retry actions operate only on the newest unresolved targets.

## Settings sync tools

<ScreenshotFigure
  darkSrc="/assets/app-captures/settings-sync-tools-dark.png"
  lightSrc="/assets/app-captures/settings-sync-tools-light.png"
  alt="Plekt Sync Tools settings showing repair and force-sync controls"
  caption="Sync Tools contains recent repairs, full watch-state sync, and deliberate import or source-of-truth actions."
/>

The detailed controls live under [Settings → Sync](/docs/settings/sync/).

See [Settings](/docs/settings/) for every field, but remember that the actions
have different scopes:

### Repair Recent Items

Revisits recent watch records and attempts to repair incomplete delivery or matching state.

Use this for a small recent problem before starting a library-wide operation.

### Full Sync Watchstates

Replays canonical watched and resume state to configured media servers in two phases.

It takes a fixed snapshot, reports progress and throughput, and uses the shared sync lock so
it cannot overlap Force Sync or backup restore.

Stop controls cancel future batches.

Completed batches remain applied.

### Force Sync

Force Sync has two deliberate directions:

- **Set Plekt as Source of Truth** replays local watched and resume state to one selected
  destination or all destinations, overwriting the selected destination's state.
- **Import Watched Status** reads watched state from one selected media server or all
  configured servers and adds missing records locally. It does not send those changes back
  out or remove local state.

Before confirming a Force Sync, check the direction and destination scope.

Keep the activity panel open and review the per-destination result after completion. For an
all-destination title push, local media-server writes complete before the Trakt phase starts.
Trakt history writes are paced, retried after bounded `429` responses, and cancelled between
items; the current canonical remove/add pair is allowed to finish before queued items stop.

Only applied actions count as completed. When some items are not found on a destination,
the result reads, for example, **Partially applied: 12 of 14 actions applied; 2 not found on
Emby**, followed by the missing titles. A run where nothing applied finishes as failed.

If an Emby or Jellyfin import left watches on an episode's own IDs instead of its show, use
[Repair Split Episode Shows](/docs/settings/tools/#repair-split-episode-shows).

## Sync Issues and Match Report

<ScreenshotFigure
  darkSrc="/assets/app-captures/sync-activity-issues-focused-dark.png"
  lightSrc="/assets/app-captures/sync-activity-issues-focused-light.png"
  alt="Plekt Sync Activity showing current sync issues, failed groups, and the Issues only filter"
  caption="Issues only filters Sync Activity to current problems and shows the issue and media-group counts beside the failed groups."
/>

Open [Settings → Sync → Sync Issues](/docs/settings/sync/#sync-issues-and-match-report) for unresolved jobs and the
**Cross-Platform Match Report**. Expected missing-library items remain skips and are not
treated as broken identity matches.

The report separates two different cases:

- no reliable IMDb, TMDB, or TVDB identity exists; or
- the identity is known but the destination library does not contain a matching copy.

Use the report like this:

1. Select **Rescan** to retry the listed items and rebuild their results.
2. Review the rows that remain.
3. Select **Fix All Matches** when identity choices are required.
4. Complete each title-level [Fix Match](/docs/media-details/#fix-match).
5. Rerun the scan and inspect Sync Activity.

An identified-but-missing destination is a library difference, not necessarily a broken
archive.

Cross-platform match issues counted in the Sync Activity header are also listed in the
attention panel at the top of Sync Activity. Each has **Fix match** to correct the identity and
**Remove** to keep the local history but stop reporting that unresolved match.

Adding the title to that server allows a later catch-up to apply the local state.

## Sync History and Logs

<ScreenshotFigure
  darkSrc="/assets/app-captures/settings-logs-controls-dark.png"
  lightSrc="/assets/app-captures/settings-logs-controls-light.png"
  alt="Plekt Logs settings showing log filters and diagnostic controls"
  caption="Logs provides filters and controls for reviewing, downloading, and clearing diagnostic output."

**Sync History** shows recent synchronization and maintenance operations, including repairs,
imports, Force Sync, and restore work.

The [Settings → Logs](/docs/settings/logs/) page contains the server and browser diagnostic stream. Each expanded activity
group also provides **Download all logs**, which saves the group's events as one plain-text
log for local review. Redact private values before sharing any exported evidence.

Preserve the relevant log before clearing it.

Redact webhook URLs, credentials, private server names, and user-identifying data before
sharing evidence.
