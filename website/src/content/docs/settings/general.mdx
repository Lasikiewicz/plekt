General is the first Settings group to check when the instance needs account, health, or
local storage changes.

## Account

<ScreenshotFigure
  darkSrc="/assets/app-captures/settings-general-account-dark.png"
  lightSrc="/assets/app-captures/settings-general-account-light.png"
  alt="Plekt General Account settings showing administrator credential controls"
  caption="Account contains the administrator identity and password-change controls."
/>

Account manages the administrator login used to access Plekt.

- **Username** identifies the dashboard account.
- **Current password** verifies an existing password before a change.
- **New password** and **Confirm new password** set the replacement password.
- **Save Login** stores the change and signs out other active dashboard sessions.

Sign in again with the new credentials after a password change. Keep credentials out of
screenshots, issue reports, and shared logs.

## System Integrity

<ScreenshotFigure
  darkSrc="/assets/app-captures/settings-general-integrity-dark.png"
  lightSrc="/assets/app-captures/settings-general-integrity-light.png"
  alt="Plekt General System Integrity settings showing health and diagnostic controls"
  caption="System Integrity provides a compact health refresh and a deeper diagnostic run."
/>

Use System Integrity before a large repair, after restoring data, or when several features
fail together.

- **Refresh Sync Health** loads a compact snapshot of database rows, storage, and outbound
  request pressure.
- **Run System Diagnostic** runs the detailed connection and scheduler checks in sequence.

An integrity warning is a starting point for investigation, not a reason to wipe data. Follow
the named feature guide and review [Logs](/docs/settings/logs/) for the first useful error.

## Privacy

Privacy holds one optional switch, **Send an anonymous daily check**. It lets the maintainer
count how many installs are active and which versions they run. It is off until you turn it on.

<ScreenshotFigure
  darkSrc="/assets/app-captures/settings-general-privacy-dark.png"
  lightSrc="/assets/app-captures/settings-general-privacy-light.png"
  alt="Plekt Privacy settings with the anonymous daily check switch on, what is and is never sent, and the exact message shown"
  caption="The Privacy panel prints the exact message before you turn the check on."
/>

- **What is sent:** at most once a day, a small message saying Plekt is running, with its
  version, release type, and CPU type, plus flags saying whether this is a new install or its
  first check of the week or month.
- **What is never sent:** your name, server address, library, watch history, connected
  services, or any install ID. The receiving server still sees the connection's IP address, as
  any website does.
- **Exactly what is sent:** the panel prints the message, so you can read it before turning
  the switch on. Turning it off stops it straight away.

The status line under the switch reads **Off. Nothing is sent**, or **On** with the time of the
last send. The switch is greyed out in the public demo. If you have not answered yet, Plekt
asks once with a **Help count Plekt installs?** card for the administrator; **Keep it off**
leaves it off, and you can change your mind here at any time. The check also runs on alpha and
develop builds.

## Storage and cache

<ScreenshotFigure
  darkSrc="/assets/app-captures/settings-general-storage-cache-dark.png"
  lightSrc="/assets/app-captures/settings-general-storage-cache-light.png"
  alt="Plekt General Storage and cache settings showing cache statistics and cleanup controls"
  caption="Storage and cache reports local data usage and lets you refresh or clear derived artwork cache."
/>

Storage and cache reports the data directory and artwork cache.

Use **Refresh Cache Stats** when you need an up-to-date count or size. Clearing the image cache
removes cached posters, backdrops, and cast profiles, but it does not remove watch history.
Plekt fetches the images again when a page needs them.

If artwork is still missing after a refresh, check [Metadata](/docs/settings/metadata/) and
then follow [the metadata troubleshooting guide](/docs/troubleshooting/#refresh-metadata-did-not-update-a-title).
