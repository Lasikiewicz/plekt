Backup protects the local archive and, when enabled, the broader Plekt instance state.
Watch History and full Plekt backups have separate schedules and retention settings. Full
backups keep the seven most recent by default (the retention count), and local and remote full
backups each have their own retention count.

## Local backups

  lightSrc="/assets/app-captures/settings-backup-local-light.png"

  caption="Local backups separate daily watch-history snapshots from encrypted full-instance backups."

The Local section provides separate Watch History and Plekt backup options.

For Watch History, set the local backup time, retention count, and daily-backup toggle, then
use **Save Schedule** or **Back Up Now**.

For a full encrypted Plekt backup, use a passphrase of at least 12 characters. **Remember
passphrase** allows scheduled backups to run without a browser open, storing the passphrase
encrypted in server configuration. Leave it off when the passphrase must stay browser-only; in
that mode only **Back Up Now** is available.

Full encrypted backups are gzip-compressed and streamed in chunks, keeping files small (around
19 times smaller on typical libraries) and checking for damaged files before restore. Older
uncompressed backups still restore cleanly, while compressed full backups require a Plekt
release with backup compression support. Keep a pre-upgrade backup before rolling back to an
older release.

Losing the passphrase means the encrypted backup cannot be decrypted. A full backup can contain
saved settings, API keys, and server credentials, so keep files and passphrases protected.


The Watch History backup status reports running or failed restores. Automated sync waits
while a restore is active; Plekt automatically recovers stale operation locks after an
interruption so playback tracking and history updates can resume. Review the reported error
before retrying, and use **Clear Status** only when no restore is still running.
Manual watched-status edits remain available. See [Restore](/docs/settings/restore/).

## Remote backups

<ScreenshotFigure
  darkSrc="/assets/app-captures/settings-backup-remote-dark.png"
  lightSrc="/assets/app-captures/settings-backup-remote-light.png"
  alt="Plekt Backup settings showing remote backup schedule, encryption, and destination controls"
  caption="Remote backups mirror Watch History and encrypted full backups to one or more enabled destinations."
/>

Remote backups mirror the selected backup family to any enabled destination using streaming
uploads. Plekt supports five destination types in Settings and [Guided Setup](/docs/onboarding/):

- **Dropbox** — one-click sign-in through Plekt's built-in OAuth flow (default folder
  `/Plekt Backups`; defaults to retaining 2 full backups unless overridden). See the
  [Privacy Policy](/privacy/) for how Plekt handles connected services and backups.
- **Backblaze B2** — S3-compatible endpoint, bucket, key ID, optional prefix, and application key.
- **S3-Compatible** — AWS S3, Cloudflare R2, MinIO, Wasabi, and other S3-compatible providers.
- **WebDAV** — Nextcloud, ownCloud, Hetzner Storage Box, or NAS WebDAV servers.
- **External / Mounted Folder** — an absolute path outside Plekt's built-in `data/backups/`
  directory, such as a NAS share, external drive, Docker mount, or synced folder.

The shared **Remote Schedule & Encryption** section sets the daily upload time, default
retention, and encryption passphrase. Added destinations appear as expandable cards, with enabled
destinations listed first. Each destination independently configures:

- whether to receive **Watch History** backups, **Full Encrypted Plekt** backups, or both;
- optional per-type retention overrides;
- on-demand **Back Up Now** actions and latest upload status per backup type; and
- a collapsible **Setup Guide** with provider-specific instructions.

To add or update a destination:

1. Open **Remote** and choose **+ Add remote destination** (or expand an existing card).
2. Select the destination type, complete the connection or sign-in fields, and enable it.
3. Choose which backup families to mirror and any retention overrides.
4. Save, then use **Test** to verify access.
5. Run **Back Up Now** and verify the upload status and remote file.

Deleting a destination record does not delete files already stored remotely. Destination secrets
are stored encrypted at rest and never prefilled in the browser; changing a destination's URL,
endpoint, or app credentials clears previously stored secrets so they cannot be sent to a
different host.
