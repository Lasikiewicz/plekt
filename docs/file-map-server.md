# File map: server

Part of the file map (with [file-map-public.md](file-map-public.md) and [file-map-repo.md](file-map-repo.md)). To look up a route or an exported function, use the generated [code-index.md](code-index.md). The architecture overview is in [architecture.md](architecture.md).

## `server/`

| File | What it is |
| --- | --- |
| `server.js` | **Process entrypoint.** Express app: access logging (rotating `data/logs/access.log`, secrets redacted), security headers + dynamic CSP, rate limiters, raw-body capture for `/api/*` → `dispatch()` (with session-bound active-tenant context and `/u/:tenant/api/*` routing), static mounts for `/media` and `public/`, `/health`, `/changelog.json`, SPA fallback, the per-minute scheduler tick, the Plex notification listener startup, and graceful shutdown. |
| `src/index.js` | **The API router.** `dispatch()` strips `/api/` and routes paths to `handleX` functions exported by `src/routes/*.js`. The full route table is the body of `dispatch()`; feature behavior belongs in the owning route module. |
| `src/db.js` | Opens `data/plekt.db` (or existing `data/plembfin.db`) via better-sqlite3 (WAL), applies concurrency-safe migrations, and exposes helpers plus the SQLite-backed cache version observed by every process. |
| `src/schema.sql` | Authoritative table definitions. See [sqlite-schema.md](sqlite-schema.md). |
| `src/appConfig.js` | Resolves admin credentials + secrets from env / `data/config.json` (scrypt password hash, generated API key / webhook secret / session secret), warns about insecure config at startup, exports `AUTH`, `verifyWebhookToken`, `rotateWebhookSecret`, `updateAdminCredentials`. |
| `src/env.js` | Minimal `.env` loader (`loadLocalEnv`) - parses `<repo>/.env` without a dotenv dependency; env vars already set take precedence. |
| `src/paths.js` | Resolves `DATA_DIR` and every path under it (`MEDIA_DIR`, `POSTERS_DIR`, `BACKDROPS_DIR`, `PROFILES_DIR`, backup dirs, `DB_PATH`, `CONFIG_PATH`, `PUBLIC_DIR`); `ensureDataDirs()` creates them. |
| `src/utils/tenancy.js` | Multi-user registry (`users.json`), scrypt password hashing, name validation, account management (`addUserAccount`, `setUserPasswordAccount`, `signOutUser`, `setUserDisabled`, `setUserStopped`, `renameUserAccount`, `removeUserAccount`), and per-user data-folder paths for single-process tenancy. Multi-user mode turns on when a non-admin user exists. |
| `src/utils/userContext.js` | AsyncLocalStorage for the active user name and data folder on a request. |
| `src/utils/tenantDatabase.js` | Opens, caches, and closes per-user SQLite databases (schema.sql + migrations) without spawning a process; does not replace the admin `db` singleton. |
| `src/utils/tenantRouting.js` | In-process `/u/<name>/api/*` rewrite into `dispatch()` under that user's context, returning 503 when a user instance is stopped and 404 when unknown or disabled. |
| `src/utils/sharedMetadataStore.js` | Install-wide SQLite store (`data/shared-metadata.db`) for shared provider metadata caches (`tmdb_*`, `tvdb_*`, `omdb_cache`, `fanart_cache`, `youtube_meta_cache`), shared metadata API keys (`tmdb`, `tvdb`, `fanart`, `omdb`, `youtube`), shared TVDB bearer token, and one-time warm-cache migration from the admin database. |
| `src/scheduled.js` | The background sync orchestrator: `runScheduledSync` (the per-run order of catch-up steps), per-platform resumable and Up Next catch-up (`syncRecentlyResumableFrom*`, `syncRecentlyNextUpFrom*`), and resume-progress replication (`syncResumableMedia`). The live-session, watched-import, unwatched-poll, dispatch-queue and force-sync code lives in the `utils/` modules listed in the `utils/` table. See [scheduled-sync.md](scheduled-sync.md). |
| `src/scheduler.js` | Scheduler wrapper and Plex notification listener lifecycle: per-minute tick orchestration, scheduled backup runs, watchlist/rating worker hooks, cache-backed metadata warm-up/backfill, next-airing cache refresh, startup/shutdown listener control, and Plex library-item unwatch callback. |
