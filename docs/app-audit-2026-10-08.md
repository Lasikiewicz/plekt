## P1 — address before release

### 1. Affected compression and sharp releases are locked

**Category:** Security / Performance. **Location:** [package-lock.json:701](../package-lock.json#L701), [package-lock.json:1582](../package-lock.json#L1582), [httpPerformance.js:74](../server/src/utils/httpPerformance.js#L74), [posterCache.js:159](../server/src/utils/posterCache.js#L159).

The lockfile contains `compression 1.8.1` and `sharp 0.35.4`. Compression is applied globally. Its advisory describes native memory leakage when a client disconnects during a compressed response, potentially exhausting server memory. Upgrade to **1.8.2 or later**. [Compression advisory](https://github.com/advisories/GHSA-vc2v-76pw-4v95).

Sharp's bundled librsvg advisory describes possible code execution under particular glibc Linux/runtime conditions when processing SVGs. The Docker base is Debian/glibc and the poster cache invokes sharp; this audit did not establish whether attacker-controlled SVGs can reach that path or reproduce the vulnerability. Upgrade to **0.35.5 or later** and rebuild images; validate the image-processing tests and runtime binaries. [Sharp advisory](https://github.com/advisories/GHSA-wq5f-xc86-pv6w).

**Recommendation:** Refresh the affected dependency resolutions, preserve the lockfile, rerun the full build and dependency scan, and rebuild deployment images. **Suggested command:** `$harden`.

### 2. Light-mode text contrast fails across shared and page-specific surfaces

**Category:** Accessibility / Theming. **Location:** [styles.css:19628](../public/styles.css#L19628), [styles.css:3774](../public/styles.css#L3774), [styles.css:3533](../public/styles.css#L3533), shared muted tokens at [styles.css:19552](../public/styles.css#L19552).

Verified examples: active Classic navigation **4.23:1**, sidebar sync text **4.34:1**, the Dashboard `Live` label **1.31:1**, and device text **2.77:1**. Movie metadata labels reached **2.65:1** on light card surfaces. Upcoming, Stats, and several Settings surfaces also produced contrast failures. Users with low vision lose precisely the status and metadata this app exists to expose.

Fresh History theme checks found no automated text-contrast failures in either dark style, **5 failing nodes in Classic Light**, and **4 in Modern Light**. This result applies to the History sample, not every dark screen.

**Standard:** WCAG 1.4.3. **Recommendation:** Replace fixed pale green/gray text with semantic, theme-aware colors; darken muted and selected-nav foregrounds against their actual composited surfaces. Recheck all four theme combinations and mobile overrides. **Suggested command:** `$colorize`.

### 3. Dialogs do not reliably establish, contain, or restore keyboard focus

**Category:** Accessibility. **Location:** [app.js:855](../public/app.js#L855), [settings-ui.js:160](../public/modules/settings-ui.js#L160), [edit-dialogs.js:490](../public/modules/edit-dialogs.js#L490), [media-lightbox.js:127](../public/modules/media-lightbox.js#L127).

Settings dialogs have dialog semantics and initial focus, but no Tab containment or focus restoration. After focusing Save and pressing Tab, focus left the dialog; after Escape, the active element was BODY. The lightbox opened while focus stayed on a poster button behind it. Edit/confirmation overlays also lack a shared focus lifecycle; several lack dialog semantics entirely. Background controls remain keyboard-accessible while visually covered.

**Standard:** WCAG 2.4.3 and 4.1.2; [WAI modal dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/). **Recommendation:** Adopt a shared native `<dialog>` or modal primitive with an accessible name, appropriate initial focus, inert background, Tab containment, Escape dismissal, and return to the invoking control. **Suggested command:** `$harden`.

### 4. Gallery and facts controls have missing accessible names

**Category:** Accessibility. **Location:** [media-detail-shared.js:449](../public/modules/media-detail-shared.js#L449), [media-detail-shared.js:756](../public/modules/media-detail-shared.js#L756).

Axe reported **16 unnamed image buttons** on the sampled movie and **19** on the sampled show. Deferred images do not provide a reliable name before they become exposed, and the shared image text is otherwise repeated as “Scene image.” The facts disclosure is an empty summary containing a visual span and was also flagged as unnamed on both pages. Screen-reader users cannot identify these controls or their purpose.

**Standard:** WCAG 4.1.2. **Recommendation:** Give the button its own name, such as “View scene image 3 of 16 for 12 Angry Men,” independent of deferred image loading. Give the facts summary actual text or an explicit name. **Suggested command:** `$clarify`.

### 5. Trailer playback and person-photo opening are pointer-only

**Category:** Accessibility. **Location:** [media-detail-shared.js:143](../public/modules/media-detail-shared.js#L143), [media-person.js:291](../public/modules/media-person.js#L291), [app-events.js:337](../public/modules/app-events.js#L337).

Trailer tiles use clickable divs; person gallery thumbnails use clickable images. Their markup lacks native activation and keyboard focus, and their delegated handlers operate on clicks. Trailer rails were also flagged for missing keyboard access. Keyboard users cannot reach and activate these interactions. The generated YouTube iframe also has no title.

**Standard:** WCAG 2.1.1 and 4.1.2. **Recommendation:** Use named native buttons around thumbnails, retain Enter/Space behavior, and give the embedded frame a title derived from the trailer name. **Suggested command:** `$harden`.

### 6. Chart and log scroll regions are inaccessible by keyboard

**Category:** Accessibility / Responsive. **Location:** [index.html:505](../public/index.html#L505), [index.html:2739](../public/index.html#L2739), [styles.css:5305](../public/styles.css#L5305).

The mobile monthly chart and the log terminal were flagged as scrollable regions with no focusable contents or focusable container. Keyboard users cannot reliably scroll through overflowing months or diagnostic output.

**Standard:** WCAG 2.1.1. **Recommendation:** Make the overflowing region focusable, provide a clear accessible label and focus indicator, and check arrow/PageDown scrolling. A structured text alternative to chart data would also help. **Suggested command:** `$harden`.

### 7. Visible action labels do not match their accessible names

**Category:** Accessibility. **Location:** [personal-media.js:388](../public/modules/personal-media.js#L388), [personal-media.js:418](../public/modules/personal-media.js#L418).

The visible text “Add to watch list” is overridden by a name such as “Add 12 Angry Men to your watch list.” Inserting the title and “your” breaks the visible phrase. Playlist actions have the same pattern. Axe confirmed one mismatch on the movie sample and two on the show. Voice-control users cannot consistently activate the control using the words they see.

**Standard:** WCAG 2.5.3. **Recommendation:** Start the accessible name with the complete visible label, then append context, e.g. “Add to watch list: 12 Angry Men.” Apply this to subsequent state updates too. **Suggested command:** `$clarify`.

### 8. Several action targets fail minimum size and spacing

**Category:** Accessibility / Responsive. **Location:** [styles.css:13209](../public/styles.css#L13209), [styles.css:13334](../public/styles.css#L13334), [styles.css:9656](../public/styles.css#L9656), [styles.css:20746](../public/styles.css#L20746).

Desktop sidebar Sync and Version targets measured about **14px and 19px high** and failed the spacing exception. Numerous desktop poster menus/settings targets were flagged too. At 390px, rating actions on Watchlist/Playlists/Ratings measured roughly **16–17px high**, with insufficient separation from other targets. These are easy to miss or activate accidentally.

**Standard:** [WCAG 2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum): 24×24 CSS pixels or qualifying spacing. **44×44 is a useful touch target recommendation, not the universal AA minimum.**

**Recommendation:** Increase the actual interactive boxes, preserving compact visual glyphs. Make mobile rating actions comfortably tappable and recheck overlapping card navigation. **Suggested command:** `$adapt`.

## P2 — next improvement pass

### 9. proxy-addr has a critical advisory, with unobserved triggering configuration

**Category:** Security. **Location:** [package-lock.json:1366](../package-lock.json#L1366), [server.js:143](../server/server.js#L143).

The lockfile contains `proxy-addr 2.0.7`; npm reports a critical IP-spoofing advisory. The described attack requires certain IPv6/mapped-IPv4 trust subnet definitions. This checkout configures **numeric `trust proxy = 1`**, not the implicated subnet form, so this audit does **not** establish exposure to that specific exploit. Nevertheless, the vulnerable dependency should be removed from the release baseline. [Proxy-addr advisory](https://github.com/advisories/GHSA-jqcg-44mw-7w3h).

**Recommendation:** Resolve **2.0.8 or later**, verify proxy/IP rate-limit behavior, and retain explicit deployment proxy assumptions. **Suggested command:** `$harden`.

### 10. Poster menus advertise menu semantics without menu keyboard behavior

**Category:** Accessibility. **Location:** [poster-menu.js:300](../public/modules/poster-menu.js#L300), [poster-menu.js:525](../public/modules/poster-menu.js#L525).

Dropdowns use `role="menu"`/`menuitem`, but opening one with Enter leaves focus on the trigger; ArrowDown did not move into the menu. The document handler only handles Escape. Portaling the dropdown to the end of BODY makes reaching it by ordinary Tab navigation cumbersome. Mouse actions still work, so a workaround exists.

**Recommendation:** Move focus into the menu on activation, implement arrow/Home/End behavior and return focus on dismissal, or use a simpler disclosed button list with appropriate focus placement. **Suggested command:** `$harden`.

### 11. Every route loads a large shared stylesheet and hidden page shell

**Category:** Performance. **Location:** [index.html:26](../public/index.html#L26), [styles.css](../public/styles.css), [styles-modern.css](../public/styles-modern.css).

Measured decoded resource sizes: `styles.css` **744,960 bytes**, `styles-modern.css` **58,110 bytes**, and HTML **235,388 bytes**. Both stylesheets load globally, even in Classic. CSS is roughly 32,000 lines. Compression and immutable caching reduce network transfers, but not all parsing, style matching, and hidden-shell DOM costs. No LCP/INP regression was proven; these are measured payload costs and optimization opportunities.

**Recommendation:** Measure cold-load LCP/style work on a mid-range phone, consolidate repeated overrides, and move isolated route styles and heavy hidden panels into deferred route resources while preserving theme first paint. **Suggested command:** `$optimize`.

### 12. Sign-in actively discourages password-manager support

**Category:** Accessibility / Usability. **Location:** [index.html:193](../public/index.html#L193).

The login form and credential inputs use `autocomplete="off"` plus LastPass/1Password ignore attributes. This increases typing and memory demands, undermines strong unique passwords, and makes signing in harder for users relying on assistive credential tools. Browser behavior can vary, so this is not claimed as a universal inability to paste or autofill.

**Recommendation:** Use `autocomplete="username"` and `autocomplete="current-password"`, remove password-manager suppression, and verify autofill and paste with the existing local authentication flow. **Suggested command:** `$harden`.

### 13. Documented module size limits are substantially exceeded

**Category:** Maintainability / Performance risk. **Location:** [frontend.md:16](frontend.md#L16), [app.js](../public/app.js), [sync-activity.js](../public/modules/sync-activity.js), [edit-dialogs.js](../public/modules/edit-dialogs.js).

The frontend document sets app.js below 3,000 lines and feature modules below 1,500. Actual line counts are **3,884** for app.js, **3,409** for sync-activity.js, and **2,157** for edit-dialogs.js; **12 modules** exceed the feature hard limit. This increases review and regression risk and weakens the intended separation of responsibilities. Size alone is not proof of runtime slowness.

**Recommendation:** Split by cohesive responsibilities, starting with shared dialog infrastructure and sync activity rendering; preserve route dependencies and lazy callback behavior. Add a proportionate size gate or update the documented limits with a deliberate rationale. **Suggested command:** `$harden`.

## Systemic patterns

1. Shared components multiply failures: sidebar contrast and targets recur on many routes; detail naming failures recur for every gallery item.
2. Focus management is implemented independently across dialogs and menus. A shared primitive would fix multiple workflows and prevent recurrence.
3. Theme tokens coexist with hard-coded text colors and many later overrides. Light-mode misses are the visible consequence.
4. Regression coverage is strong for data behavior and source contracts but does not catch these rendered accessibility defects. Add focused browser coverage for shared dialogs, action naming, contrast, and target spacing rather than snapshotting every screen.
